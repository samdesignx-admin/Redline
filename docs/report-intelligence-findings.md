# UXNest Report Intelligence — Phase 0 Findings

**Status:** Investigation complete  
**Scope:** Investigation only; no application behavior changed.

## Baseline investigated

The investigation baseline was commit `47cb346` on `refactor/platform-foundation`.

## Confirmed score inconsistency

The Executive Summary and Final Scorecard are generated by separate parallel AI batches. Each batch emits an overall score independently:

- Executive Summary → `summary.score` → report cover and summary surfaces.
- Final Scorecard → `scorecard.overall` → scorecard and related report surfaces.

Neither batch shares the other batch's generated score, so agreement is coincidental. The overall score is also not currently derived from the five dimension scores.

**Decision:** Phase 1 preserves current score semantics. Phase 2 will introduce one deterministic canonical overall score derived from the five canonical dimension scores.

## Screenshot and visual-evidence constraints

- Screenshot audits have source images available in browser memory during the live audit session.
- URL audits do not currently capture screenshots.
- Audit records persist metadata and report text, not source image files.
- Therefore visual annotations for saved audits or URL audits require new storage and/or screenshot-capture infrastructure.

**Decision:** Screenshot persistence and URL screenshot capture are deferred and are not part of Phases 1–4.

## Other report-model gaps

- Findings have no stable IDs.
- Recommendations, Top 10, Quick Wins, and Strategic Improvements are generated independently and have no source-finding traceability.
- Findings from parallel sections are not deduplicated across the report.

## Resolved implementation direction

1. Phase 1: canonical report normalization, canonical dimensions, stable finding IDs, and backward-compatible parsing.
2. Phase 2: one deterministic overall score consumed by every report surface.
3. Phase 3: evidence status and confidence, with minimal prompt/output-contract changes if required.
4. Phase 4: deduplication and recommendation traceability.
5. Visual evidence architecture is reviewed separately after the report foundation is stable.
